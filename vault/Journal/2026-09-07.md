## Problems Encountered

- On [[ansible01]], suspending `vi` with Ctrl-Z (repeatedly) left a stale swap file at `/etc/.chrony.conf.swp` and blocked re-editing `/etc/chrony.conf`.
- `ssh <host> "sudo …"` failed with `a terminal is required to read the password` — a non-interactive SSH command has no TTY for the sudo prompt.
- The ISO was not mounted on either node, and neither had an `/etc/fstab` entry. [[managed01]] inherited the repo config and a connected ISO from the [[ansible01]] clone but never a mount, so its package source was silently absent after every boot.
- `mount -a` and `findmnt --verify` warned that systemd was still using the old `/etc/fstab`.

---

## Solutions

- Killed the backgrounded `vi` (`jobs -l`, `kill -9 <pid>`), removed the swap file, re-edited cleanly. For single-line changes, `sudo tee -a` avoids the editor entirely.
- Read the world-readable `/etc/chrony.conf` with a plain `diff` (no sudo); ran privileged one-offs from an interactive shell.
- Added `/dev/sr0  /mnt/rocky-iso  iso9660  ro,nofail  0 0` to `/etc/fstab` on both nodes; `nofail` keeps boot safe if the ISO is ever detached.
- Ran `systemctl daemon-reload` after editing `/etc/fstab`, then `mount -a`; verified with `findmnt`.

## Concepts Learned

- A passphrase-less SSH key is the entire credential; it should never leave the control node or enter version control.
- `chrony`'s `local stratum N` serves time the host isn't itself synced to; `allow` is required before chrony answers any client.
- Stratum shows the distance (number of NTP server layers) from an NTP reference clock source.
	- Stratum 0 is the reference hardware itself.
- `timedatectl` "System clock synchronized" reports whether this host trusts its own clock; an NTP server with no upstream reads "no" while still serving clients correctly.
- systemd caches `/etc/fstab` edits need `daemon-reload` before `mount -a` sees them.
