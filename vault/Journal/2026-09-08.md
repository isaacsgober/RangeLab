## Problems Encountered

- `ansible.builtin.authorized_key` would not resolve — the module lives in `ansible.posix`, which `ansible-core` does not ship and which cannot be installed offline (the same wall as `ansible-lint`).
- A `--check` run passed, then the real run failed: `/etc/systemd/journald.conf.d/` did not exist. `--check` does not fully validate `copy` destinations.
- The journald drop-in had CRLF line endings (authored on Windows, `scp`'d past git's `eol=lf`). journald silently ignored `Storage=persistent`. Even after fixing that, a live `systemctl restart` did not migrate to persistent storage.
- Logged into [[ansible01]] as `labadmin` and ran the playbook from `labadmin`'s home — `become` failed (no `NOPASSWD` for `labadmin`), [[managed01]] was unreachable (no outbound key in that home), and `rm -rf` on the wrong path deleted the working copy at `/home/ansible/Ansible`.
- [[managed01]] shared [[ansible01]]'s `/etc/machine-id` — the clone reset never took.

---

## Solutions

- Replaced `authorized_key` with `file` + `copy` managing `authorized_keys` directly.
- Added a `file` task ensuring `/etc/systemd/journald.conf.d/` before the `copy`.
- Converted the drop-in to LF with a trailing newline; added a `/var/log/journal` `file` task and a `journalctl --flush` handler ordered after the restart, so the playbook reaches persistent storage without a reboot.
- Re-established the working copy at `~ansible/Ansible`; run the playbook **only** as the `ansible` account.
- Regenerated [[managed01]]'s machine-id with `systemd-machine-id-setup` and rebooted.

## Concepts Learned
- Ansible plays
- Ansible checks don't catch everything.
- Idempotency comes from declaring desired state. `state: present` is idempotent; `state: latest` re-checks every run.
- Handlers run in the order they are **defined**, not the order they are notified.
- "Playbook succeeded" means files were placed and services bounced — not that the OS reached the described state.
- Ansible here is configuration management, not provisioning. One-time image prep (machine-id, host keys) belongs in a separate playbook or a manual checklist.
