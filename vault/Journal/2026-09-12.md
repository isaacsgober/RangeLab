## Completed

- Extracted the VM-list request into `list_vms(host, token, timeout=5)`, returning the
  parsed JSON instead of printing it - same move as Phase 4's `check_host()` returning a
  value instead of printing directly.
- Attempted the same for `login()`, plus wrapping the remainder in `main()`, solo.
  Introduced two bugs in the process, found with help after reporting "always returns a
  401 now":
  - `login()`'s `else:` returned `response.text` (the raw JSON body, quote marks and all)
    instead of `response.json()` (the parsed string). The stray quote characters meant the
    session-ID header on every later request never matched a real session - an always-401
    that had nothing to do with the actual credentials.
  - `list_vms()`'s `else:` returned `vm_response.json` - missing the `()`. A reference to
    the method itself, not its result. The exact mistake flagged as a common one a few
    days earlier, now hit for real.
- Fixed both; reran clean (`[]`, as expected, same known result as before).
- Moved `user = input(...)` and `password = getpass.getpass(...)` from module level into
  `main()`. They used to fire the instant the file was loaded - including on a plain
  `import` - which would block any other script trying to reuse `list_vms()` for something
  unrelated. Directly undermined the point of the refactor. `host` stayed at module level;
  a plain string literal has no such side effect.
- Added docstrings to `main()`, `login()`, and the module itself. The module docstring
  specifically notes that `login()` / `list_vms()` are meant to be reused - information no
  function-level docstring carries, since an importer might never look at `main()` at all.

---

## Problems Encountered

- Both bugs above were introduced doing the refactor unassisted, and both were silent  - 
  no crash, just a wrong result (a 401 in one case, would have been a nonsense printed
  object in the other had the first bug not masked it).
- Old habit collision: `return (True, message)` in `healthcheck.py` was correct - a comma
  inside the parens makes it a tuple. Carrying the same `return(x)` shape over to a
  single-value return elsewhere isn't wrong, just meaningless, and worth knowing precisely
  why rather than pattern-matching the syntax.

---

## Solutions

- `response.json()` parses the JSON body; `response.text` gives the raw text, quote
  characters and all.
- `vm_response.json()` - with the call - returns the parsed data; without it, a bound
  method object.
- Moved the two blocking calls inside `main()`, behind the same `if __name__ ==
  "__main__":` guard already protecting the rest of the entry point.

---

## Concepts Learned

- `.attribute` reads data already sitting on an object; `.method()` - with the call - runs
  code and returns its result. Dropping the parens yields a reference to the method, not
  an answer.
- A docstring isn't a comment. Python keeps it as `__doc__`; a `#` comment is discarded at
  parse time and never exists at runtime.
- A module docstring and a function docstring serve different readers: the module one is
  the only summary someone importing a single function ever sees, without needing to know
  any other function in the file exists.
